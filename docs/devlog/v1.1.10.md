## 修复内容

### iflytek + vivo detail URL — Beisen SPA 不认 `/jobs?jobAdId=`

**文件：** `cli/src/iflytek.ts:53-83`, `213-220`；`cli/src/vivo.ts:51-81`, `205-217`, `355-369`

**根因：** 两家公司都跑在 `*.zhiye.com`（北森招聘 SaaS）上，共用同一套 `pc-app-*.chk.js` bundle。route table extract:

```
path:"/campus/detail"   path:"/campus/jobs"
path:"/social/detail"   path:"/social/jobs"
path:"/intern/detail"   path:"/intern/jobs"
path:"/jobs"            (list only — NO /jobs/:id)
```

旧 URL `/jobs?jobAdId=<id>` 匹配 `path:"/jobs"`（list 路由），SPA 把所有 ID 都当成"展开列表 + 高亮"，并未渲染详情页 component。Bundle 里 URL builder 直接写死了 detail-route 三选一：

```js
if(t===i.detail) switch(n){
  case r.social: return "/social/detail";
  case r.campus: return "/campus/detail";
  case r.intern: return "/intern/detail";
}
```

参数读取也确认 `?jobAdId=<id>` 是对的：`recruitment-portal-*.chk.js` 内 `new URLSearchParams(location.search).get("jobAdId")`。

**修复：** 两个文件分别新增同名 helper（不抽成 shared module，俩文件总共 18 行重复，YAGNI）：

```ts
function businessTypeForJob(
  categoryId?: string,
  category?: string,
): "campus" | "social" | "intern" {
  // Beisen-standard numeric codes (3=intern, 4=social, 5=campus).
  if (categoryId === "3") return "intern";
  if (categoryId === "4") return "social";
  if (categoryId === "5") return "campus";
  const label = (category ?? "").toString();
  if (label.includes("实习")) return "intern";
  if (label.includes("校园") || label.includes("校招")) return "campus";
  if (label.includes("社招") || label.includes("社会")) return "social";
  return "social";
}

const DETAIL_PAGE = (
  id: string,
  businessType: "campus" | "social" | "intern" = "social",
) =>
  `https://<tenant>.zhiye.com/${businessType}/detail?jobAdId=${encodeURIComponent(id)}`;
```

派生顺序：CategoryId 数字码（最权威，标准 Beisen 字典）→ Category 文本子串匹配（iflytek 的 label "校园招聘"、vivo 的 label "员工社招" 都覆盖到）→ 默认 social。

调用点：`summarize(item)` 和 vivo `fetchPositionDetail` 都补上了 businessType 参数。iflytek 的 `fetchPositionDetail` 用 `summary.apply_url`，自动继承。

**实测：**

```
iflytek post_id=190816475 (校园招聘 / CategoryId=5):
  → apply_url: https://iflytek.zhiye.com/campus/detail?jobAdId=190816475

vivo post_id=561210681 (员工社招 / CategoryId=4):
  → apply_url: https://vivo.zhiye.com/social/detail?jobAdId=561210681
```

旧 URL 和新 URL 都返回相同 31KB shell（北森 SPA 全站一个 shell），区别在客户端路由 — route table 是唯一权威，所以验证靠 SPA bundle 而非 body diff。
