## 修复内容

### meituan detail URL — `/job-list/<id>` 完全是错的路由

**文件：** `cli/src/meituan.ts:171-182`, `383-399`, `600-614`

**根因：** `DETAIL_PAGE` 之前是 `https://zhaopin.meituan.com/job-list/${jobUnionId}` — 这个路径在美团服务器上根本不存在。Server 对所有非 `/web/...` 的路径都 302 重定向到 `/web/social` 列表页（这是 catch-all redirect）。所以任何 `/job-list/<id>` 包括根本错误的 ID，最终都会落到同一个列表页 — 用户点链接看不到对应职位。

研究方法（agent 抓 SPA bundle）：

1. 抓 `/web/social` 主 JS bundle (`entry-main-*.js`)
2. grep 路由表，找到 React Router 注册 `path:"/position/detail"`
3. 同一个 bundle 里的 `linkUrl:"/position/detail?jobUnionId=3524979618&highlightType=campus"` 是写死的分享链接模板，confirms 参数 shape
4. 验证: `https://zhaopin.meituan.com/web/position/detail?jobUnionId=4479782490&jobShareType=1&highlightType=campus` → 200 OK, 不再 302 重定向

**修复：** `DETAIL_PAGE` 改成接受 `jobUnionId` + 可选 `jobType`，输出 `/web/position/detail?jobUnionId=...&jobShareType=1&highlightType=<campus|social>`。`highlightType` 派生规则：

```ts
function highlightTypeForJobType(jobType?: string): "campus" | "social" {
  return jobType === "3" ? "social" : "campus";
}
```

来自 bundle 里的 helper `de()` — jobType 1 (校招正式) / 2 (实习) → `campus`；jobType 3 (社招) / SOCIALBOLE → `social`。

**调用点更新：**

- `summarizePosition` (L383) — 用 `jobTypeCode` 已有变量传入
- `fetchPositionDetail` (L613) — 用 `raw.jobType`（`RawJobDetail extends RawJobListEntry` 自带 `jobType`）
- `referer: DETAIL_PAGE(id)` (L582) — 不传 jobType 默认 campus，对 Referer header 不影响 API 行为

**Body diff 注意：** 新 URL 真实 / bogus ID 都返回 33266B 的 SPA shell，content 由 SPA runtime 抓取 — `<title>美团招聘</title>` 不变。但 URL 不再被 server 重定向走，SPA 客户端能正常用 jobUnionId 调 `POST /api/official/job/getJobDetail` 渲染详情。这是 SPA-runtime fetch 模式，curl 只能验"没被 redirect 走"，要 100% 端到端还要 headless 浏览器。
