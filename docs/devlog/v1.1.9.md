## 修复内容

### unitree detail URL — 路由要 numeric snowflake ID，不是 JobCode

**文件：** `cli/src/unitree.ts:58-69`, `113-220`, `375-388`

**根因：** `DETAIL_URL` 之前用 `https://www.unitree.com/position/${jobCode}`（jobCode 形如 `J10126`），但宇树 Nuxt 站只注册了 `/position/<numericSnowflakeId>` 路由（id 形如 `1569894802328125440`）。`/position/J10126` 直接 HTTP **404**。

列表页 HTML 把 jobCode 和 numericId 配在同一个 `<a>` 里：

```html
<a href="/position/1569894802328125440" class="link" ...>
  <p class="title">解决方案工程师(J10126) ...</p>
</a>
```

旧 parser 一上来就 `stripTags(html)` 把 href 全扔了，只能从文本里拿到 jobCode。

**修复：**

1. 新增 `extractJobCodeToNumericId(html)` 在 strip 前用 regex 抓 href ↔ jobCode mapping：

   ```ts
   const linkPattern =
     /<a[^>]*href="\/position\/(\d+)"[^>]*>\s*<p[^>]*class="title"[^>]*>[^<]*\(J(\d+)\)/g;
   ```

2. `parsePositions` 先建 map，再走原来的 stripTags + regex pass。每个职位 `apply_url = numericId ? DETAIL_URL(numericId) : POSITION_PAGE`（map miss 时降级到列表页）。

3. `DETAIL_URL` 签名改成 `(numericId: string)` — 参数名换成 numericId 更不会写错。

4. `getPosition` (L386) 之前 fallback 是 `DETAIL_URL(id)` 其中 `id` 是 JobCode → 拼出来必然 404。改成 fallback `POSITION_PAGE`（列表页）。

**验证：**

```bash
$ curl -sIL "https://www.unitree.com/position/1569894802328125440"
HTTP/2 200, 33297 bytes (SPA shell, SPA 客户端会再调 API 拿详情)

$ curl -sIL "https://www.unitree.com/position/99999999999"
HTTP/2 404, 5037 bytes (server-side 验证 ID 存在性)

$ npx tsx src/index.ts unitree search | jq -r '.positions[0]'
{
  "post_id": "J10126",
  "title": "解决方案工程师",
  ...
  "apply_url": "https://www.unitree.com/position/1569894802328125440"
}
```

post_id 仍然保持 JobCode 形式（用户能看的对外标识），URL 里用 numericId。
