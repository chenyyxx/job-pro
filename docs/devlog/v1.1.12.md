# v1.1.12 开发日志

> 发布日期：2026-05-24

## 这一轮做的事

把 URL 体检的覆盖范围从「每家公司 1 个 scope」扩到「(adapter × scope) 全矩阵」。50 个 adapter × 3 个 scope，跑全矩阵后发现一个**跨 7 家公司的系统性 bug**：Moka SaaS factory 把 detail URL 拼成了复数 `#/jobs/<id>`，但所有 Moka 租户实际注册的是单数 `#/job/<id>`。

## 矩阵审计方法

派了 5 个并行 research agent (每个 10 家)，每家跑 `--scope campus/social/intern`，提取 apply_url，并 grep 出哪些 adapter 的 DETAIL_PAGE 是 scope-conditional 的。然后我自己用 agent-browser + curl 对每个 scope 分支做了浏览器验证。

## 修复内容

### moka factory — 复数 `/jobs/` 改单数 `/job/`

**文件：** `cli/src/moka.ts:376, 612, 734`

**根因：** Moka SaaS（app.mokahr.com）的 SPA 路由是 `#/job/<uuid>` (singular)。`/jobs` 是 list 路由 (`#/jobs` 显示岗位列表)。`#/jobs/<id>` 在 SPA 里被 Vue Router 当成 `#/jobs?id=<id>` 解析，路径段不匹配 → 渲染 list 页。

之前 v1.1.11 的 weibo 修复是同样的 bug，但只改了 weibo.ts 局部 — 没意识到这是 moka factory 通用 bug。这次浏览器审计 cambricon social 时再次撞见，去抓 Moka list 页的 `<a href>` 看实际 URL pattern：

```bash
agent-browser open "https://app.mokahr.com/social-recruitment/cambricon/1113#/jobs"
agent-browser eval '[...document.querySelectorAll("a[href]")].map(a=>a.href).filter(h=>h.includes("#/job"))'
# →  全部是 #/job/<uuid> (singular)
```

依次复查所有 Moka 租户（cambricon, moonshot, megvii）的 list 页都用单数。确认这是 Moka 通用约定，不是 per-tenant 差异。

**修复：** sed 替换 3 处 `#/jobs/${encodeURIComponent` → `#/job/${encodeURIComponent`。影响 7 个用 Moka 的 adapter:

- moonshot, deepseek, galaxyuniversal, stepfun (social-only)
- megvii, cambricon (双 channel campus + social)
- geely (social-only)

**验证：** 浏览器复测 moonshot 单数 URL 渲染「资深后端工程师-商业化 + 完整 JD」，cambricon social 单数 URL 渲染「深度学习框架图编译工程师」，cambricon campus 渲染「分布式基础软件开发实习生-27届」。

## 未决问题（下一轮再做）

### lilith scope 过滤无效
所有 3 个 scope 返回同一批职位。Feishu factory 的 `scope` 参数没传到上游 API。Not URL bug — scope filter behavior bug。

### cicc / hikvision 没 export supportedScopes
dispatcher 默认放行所有 scope，但 Liepin factory 忽略 scope 参数。建议补上 `["social", "all"]` 声明。

### liauto 公网详情页拒识 ID（上游）
所有从 API 返回的 ID 在公网 detail 页都触发「请前往职位列表重新查找」。不是 URL pattern bug，是 lixiang.com 自己的前后端数据没联通。Not actionable from our side。

### horizon social agent-browser 空 body
浏览器测出来 body 完全为空（既没 SPA shell 也没错误）。可能是反爬或网络问题。需要再尝试。
