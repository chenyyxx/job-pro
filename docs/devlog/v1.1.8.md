## 修复内容

### netease detail URL — 需要 `.html` 后缀触发正确 entry chunk

**文件：** `cli/src/netease.ts:101-110`

**根因：** `DETAIL_PAGE` 用的是 `https://hr.163.com/job-detail?id=${id}`。Nginx 对裸路径和 `.html` 后缀都返回 6088B 左右的 shell，看起来一样。但 grep 出文末加载的 entry chunk：

- 旧 URL `/job-detail?id=75767` → `<script src="/static/js/index.488b4902.js"></script>` — **首页 entry**
- 新 URL `/job-detail.html?id=75767` → `<script src="/static/js/job-detail.620522dd.js"></script>` — 详情页 entry

两个 entry 决定 SPA 渲染哪个组件。旧路径触发首页 entry，所以用户看到的是首页 shell（这就是为什么 audit 阶段所有 ID 包括 bogus 都返回字节相同的 shell — 它们全是首页 entry 的同一个壳）。

**研究方法：** agent 反编译 `commons.288fd140.chunk.js` 找到路由表，定位到 `"job-detail"` 注册的 component chunk (`37.4e5aa32b.chunk.js`)。chunk 内的 share-URL 模板写死的就是 `.html` 形式：

```js
"".concat(location.origin,"/job-detail.html?id=").concat(a,"&showShare=1&lang=").concat(t)
window.open("job-detail.html?id=".concat(e.id))
```

确认所有 top-level 路由都遵循同样的 pattern：`/job-list.html`, `/product.html`, `/life.html`。

**修复：**

```ts
const CAMPUS_PAGE = "https://hr.163.com/job-list.html?workType=1";
const DETAIL_PAGE = (id: string) =>
  `https://hr.163.com/job-detail.html?id=${encodeURIComponent(id)}`;
```

实测 `diff`：

```
< src="/static/js/index.488b4902.js"
> src="/static/js/job-detail.620522dd.js"
```

唯一区别就是 entry chunk 名 — 这是路由是否被识别的决定性证据。
